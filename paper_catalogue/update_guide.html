Add & update papers

A growing library with no venue or year restriction. Add conference papers, journal articles, workshop papers and preprints while keeping their sources and publication status clear.

01 / Choose & verify

Start with a primary source

Use the publisher, official proceedings, OpenReview or the paper’s arXiv page. Record the exact title, author order, year, venue or source, and publication status. A preprint belongs in the library without being called an accepted paper.

  • Search the existing collection by title, DOI or arXiv/OpenReview ID first. Keep one record for the same work.
  • Write a short relevance note and a concrete limitation. Separate what the paper reports from what has been independently tested.
  • Label evidence precisely: metadata, abstract, or a named full-text passage. Add a full-text check only after reading that passage.
02 / Add the record

Send the paper link, or edit the source data

In the local project, you can ask Codex: “Add this paper to All Papers, verify its metadata and citation, categorize it, then publish the update.” Include its URL or DOI and any topic you want it filed under.

For manual additions, append an entry to paper_catalogue/additional_papers.json in the original project. New venues and years appear in the filters automatically. The example below is a template, not a paper already in the library.

Record format and editable fields 
{
  "key": "ARXIV:REPLACE_WITH_ID",
  "title": "REPLACE_WITH_EXACT_TITLE",
  "authors": ["First Author", "Second Author"],
  "year": 2024,
  "venue": "arXiv",
  "status": "Preprint",
  "source_url": "REPLACE_WITH_PRIMARY_SOURCE_URL",
  "topics": ["Training dynamics"],
  "category_codes": ["T4"],
  "summary": "One or two sentences explaining the contribution and relevance.",
  "qualification": "The assumptions, approximation, model scale or study setting.",
  "evidence": "Primary-source abstract"
}

The file is a JSON array: [{...}, {...}]. Keep a stable, unique key. Supported status values are Accepted, Published, Preprint and Working paper. Use an explicit four-digit year; journal and preprint names do not need a year suffix.

Optional fields include pdf_url, doi (identifier only), conference_url, proceedings_url, openreview_url, code_links, and verified_date (YYYY-MM-DD). Detailed topic fields include quantity, method, matrix_scope, geometry, manifold_scope, training_scope, hyperparameters, training_finding and training_caveat.

Each optional fulltext_checks entry needs url, location and note. A checked equation or passage is not a complete paper review.

topics can use existing names or new ones. category_codes is optional; use codes shown in the catalogue’s Category filter. Known categories add their corresponding topic automatically.

03 / Check the citation

Copy BibTeX directly from each paper

Use Copy BibTeX on a paper card to copy its citation in one click. View citation shows the exact entry and its source. If the browser blocks clipboard access, the site selects the citation for manual copying.

By default, the site generates a conservative @misc entry from the recorded title, authors, year and primary source. It does not guess journal details, proceedings titles, page numbers or DOIs. The per-paper entry and the complete BibTeX download use the same citation.

Use a publisher or author-provided BibTeX entry

Add an object keyed by the paper’s stable ID to paper_catalogue/citation_overrides.json. Each object needs bibtex (the complete entry as a JSON string, with newlines escaped as \n) and source_url (where that citation was obtained).

Verify that title, author order, publication year and version match the record. Keep the citation key unique across the library. Use the publisher’s @article or @inproceedings entry when available; otherwise retain the generated entry. The build checks entry structure and duplicate citation keys, but metadata accuracy still needs a source check.

04 / Preview & publish

Build, check, then push

From the original local project directory, build and validate without publishing:

python3 publish.py --prepare-only

Open the local preview. Check the new paper, its venue/year/status filters, primary-source links, notes and citation. Then publish:

python3 publish.py "Add papers on your topic"

This rebuilds the static site, commits changes in github_pages_site/ and pushes to GitHub. Pages deploys the update automatically. The website address stays the same.

Edit the original data and template files. The files in the publishing folder are generated and can be replaced during a rebuild. The website does not edit source files or save additions in your browser.

Maintaining the library

Update an existing paper without duplicating it

For a record in additional_papers.json, edit the existing object and retain its key. When a preprint is published, update the venue, status, source link, year and citation together, checking the published version.

The initial ICML 2026, ICLR 2026 and NeurIPS 2025 records still come from their historical program and curation files. Ask Codex to update those source records, or edit the relevant curation source and regenerate its selection first. Do not append the same paper again just to change its citation: use citation_overrides.json.

All Papers is a curated personal research library. Its name describes the scope of the collection, not a claim to index every paper. The initial collection is retained as the starting point.
